# Visited places map - technical documentation

## Project goal
Static site on GitHub Pages with two pages:
1. **Pins map** (`index.html`) - visited cities and landmarks marked with pins, with a legend listing places grouped by country.
2. **World map** (`countries.html`) - visited countries highlighted, with a legend listing those countries.

On both pages, hovering over a legend item temporarily highlights the corresponding map object (and vice versa - hovering a map object highlights the legend item).

No high precision required; the project is free, with no backend or separate hosting.

All code, comments, commit messages, documentation, and input files must be written in English.

## Stack
- **Hosting:** GitHub Pages (static).
- **Maps:** [Leaflet.js](https://leafletjs.com/) + [OpenStreetMap](https://www.openstreetmap.org/) tiles (free, no API keys for moderate load). Vendored locally in `assets/vendor/leaflet/`.
- **Country flags:** [flag-icons](https://github.com/lipis/flag-icons) CSS library with SVG flags. Vendored locally in `assets/vendor/flag-icons/` (CSS) and `assets/vendor/flags/` (SVGs).
- **Country borders:** GeoJSON dataset [datasets/geo-countries](https://github.com/datasets/geo-countries) (properties `name`, `ISO3166-1-Alpha-2`, `ISO3166-1-Alpha-3`), stored statically in `data/world-countries.geojson`.
- **Places/countries data:** generated by script as ES modules (`assets/js/places-data.js`, `assets/js/countries-data.js`) - no DB, no separate network JSON request.
- **Templating:** plain HTML/CSS/JS (ES modules), no bundler - GitHub Pages serves files as-is.

## Data generation

### Data source
**GeoNames** (geonames.org) - open international city database. Each city has a unique `geonameid`, coordinates, name, and **ISO 3166-1 alpha-2 country code**, matching the codes in the GeoJSON borders.
- The `cities500.txt` dump is downloaded once to `.cache/` on first run - the script runs offline without calling external APIs on subsequent runs.

### Input files

`scripts/input/cities.csv` - cities resolved via GeoNames. Columns: `name`, `geonameid` (optional, for disambiguation), `photo` (optional, filename only):
```
name,geonameid,photo
Yakutsk,,
Moscow,,
Hiroshima,,hiroshima.jpg
cherskiy,2126199,
```

`scripts/input/extra-places.csv` - custom points not in GeoNames (landmarks, temples, islands, etc.). Columns: `name`, `country`, `lat`, `lng`, `photo` (optional, filename only):
```
name,country,lat,lng,photo
Ko Phi Phi,TH,7.7407,98.7784,
Angkor Wat,KH,13.4124693,103.8644054,angkor.jpg
```

`scripts/input/mega-places.csv` - auto-generated by `collect_places.py`, same format as `extra-places.csv`. Do not edit manually.

Photos go to `assets/img/` - specify only the filename in the CSV, the script prepends the path automatically.

Coordinates can be copied from a Google Maps URL: `@13.4124,103.8644` after the `@` sign.
Country codes reference: `scripts/country-codes.csv`.

### Running
```
make generate
```
Skips cities already present in `places-data.js` (by `geonameid`). To force-regenerate all records (e.g. after adding a photo to an existing entry):
```
make generate-force
```

### Place types
Each generated record has a `type` field:
- `"city"` - from `cities.csv` (resolved via GeoNames)
- `"place"` - from `extra-places.csv` or `mega-places.csv` (custom coordinates)

The pins map legend shows 🏙️ for cities and 🏛️ for places. A **Places** toggle in the legend header lets you hide/show all place markers and their legend entries.

### Algorithm (`scripts/generate_data.py`)
1. Load GeoNames dump into an index by `name`/`asciiname`/`alternatenames` fields (lowercase).
2. Merge `cities.csv` with `mega-cities.csv` (if present), deduplicating by `(name, geonameid)`.
3. For each city in the merged list, find a GeoNames record:
   - if `geonameid` is given - look it up directly;
   - otherwise - exact name match; if multiple matches, pick the highest `population`;
   - if not found - error printed to console, generation aborted.
4. Skip cities already in `places-data.js` (matched by `geonameid`); update `photo` if it changed.
5. Merge `extra-places.csv` with `mega-places.csv` (if present), deduplicating by `(name, lat, lng)`.
6. Write results as ES modules:
   ```js
   // places-data.js
   export const places = [
     { "name": "Hiroshima", "country": "JP", "lat": 34.4, "lng": 132.45,
       "geonameid": 1862415, "type": "city", "photo": "assets/img/atomic-bomb-dome-hirosima.jpg" },
     { "name": "Angkor Wat", "country": "KH", "lat": 13.4124, "lng": 103.8644,
       "type": "place" },
     ...
   ];

   // countries-data.js
   export const visitedCountries = ["CY", "JP", "KH", "RU", "TR"];
   ```

## Collecting places from a photo library (`scripts/collect_places.py`)

Allows adding places from an existing directory tree (e.g. a Google Drive photo backup) without manually editing `cities.csv` or `extra-places.csv`.

### How it works
1. Recursively searches the base directory for `place.csv` and `city.csv` files.
2. `place.csv` format: same as `extra-places.csv` (`name,country,lat,lng,photo`). Deduped by `(name, lat, lng)`. Output: `mega-places.csv`.
3. `city.csv` format: same as `cities.csv` (`name,geonameid,photo`). Deduped by `(name, geonameid)`. Output: `mega-cities.csv`.
4. The `photo` column in both files is a filename relative to the CSV file itself.
5. Renames each photo to a slug derived from the place/city name (e.g. `Cape of Good Hope` → `cape-of-good-hope.jpg`); appends `-2`, `-3`, etc. on collision.
6. Resizes photos so the longest side is at most `--max-px` pixels (default: 1024), suppressing metadata warnings, and copies them to `assets/img/`.
7. Writes logs to `scripts/logs/collect.log` (full) and `scripts/logs/collect-errors.log` (errors only, cleared each run).

### Running
```
make collect                        # uses map_px/ as base directory
make collect BASE_DIR=D:/my/photos  # custom directory
make collect-force                  # re-process and overwrite already copied photos
make collect MAX_PX=800             # custom photo size
```

After collecting, run `make generate` to rebuild the map.

Default base directory is `map_px/` (sibling of the project root), configurable via `DEFAULT_BASE_DIR` in the script.

## How maps receive data
Since opening `index.html`/`countries.html` directly from disk (`file://`) blocks `fetch` JSON via CORS, places and countries data is not fetched over the network but imported as ES modules directly in the map JS:

```js
// pins-map.js
import { places } from './places-data.js';

// countries-map.js
import { visitedCountries } from './countries-data.js';
```
HTML does not change on data regeneration - just rewrite `*-data.js` via `make generate`.

GeoJSON country borders (`world-countries.geojson`) is a large static file still loaded via `fetch` (requires HTTP server, which GitHub Pages provides).

## Pins map rendering (`pins-map.js`)
- Creates a Leaflet map with OSM tiles, places a marker for each location from `places`.
- Builds legend `#legend-list`: places grouped by country (country name and SVG flag via `flag-icons`), 🏙️/🏛️ icon per item based on `type`.
- Hovering a pin opens a popup showing "**Name**, Country", year (if set), and photo (if set, 200px wide); mouse-out closes it.
- On hover, `setActive(id)` highlights the pin (`pin-highlight` CSS class) and scrolls the legend item into view.
- **Places toggle** (`#show-places` checkbox): hides/shows all markers and legend items with `type === "place"`.

## Countries map rendering (`countries-map.js`)
- Loads `world-countries.geojson`, colors countries via `style` callback: visited (code in `visitedCountries`) - green, others - gray.
- Builds legend `#legend-list` from GeoJSON features filtered by `visitedCountries`, sorted by name; each item includes the SVG flag.
- On hover over a country on the map or a legend item, `setActive(code)` is called:
  - layer style temporarily changes to `HIGHLIGHT_STYLE` (different fill/stroke color), on mouse-out `geoLayer.resetStyle(...)` restores the original style;
  - the corresponding legend item gains/loses class `active`.

> Known issue: Russia's polygon crosses the antimeridian (180 longitude), causing Leaflet to render part of the country on the "other side" of the map. The proper fix is to pre-split such polygons in GeoJSON along the 180 meridian (separate task, not yet implemented).

## Shared utilities (`assets/js/utils.js`)
- `countryName(code)` - English country name via `Intl.DisplayNames`.
- `countryFlag(code)` - returns `<span class="fi fi-xx"></span>` HTML for use with `flag-icons`.
- `styleFeature(visitedSet, feature)` - Leaflet style object for a GeoJSON feature.
- `groupByCountry(places)` - groups places array into a Map keyed by country code.
- `popupHtml(place)` - builds HTML for a Leaflet pin popup ("**Name**, Country", optional year, optional photo at 200px width).

## Deploy to GitHub Pages
1. In repository settings: **Settings - Pages - Source** - select branch `main` and folder `/ (root)`.
2. Files are served statically (no build step).
3. `world-countries.geojson` is already in the repository - no external requests needed.
